# 工作区关联

这是一个 DeepSeek Harness 插件，用来可视化组建 2–20 个工作区的关联组，并在每次模型请求时按当前会话目录提供组内其他项目上下文。

## 安装

在 DSH 的 **插件 / Plugins** 页面选择添加插件，填入本仓库的 GitHub 地址即可。安装后如当前页面尚未加载新插件，刷新一次 GUI。

仓库地址：<https://github.com/binsonHao/dsh-workspace-links>

## 可视化管理

打开 **设置 → 工作区关联**。页面提供完整的关联组管理，不需要通过对话或记忆命令：

1. 点击 **新建关联组**。
2. 第一个工作区默认选择当前会话所属工作区；在 **工作区目录** 中可以从 DSH 已有工作区下拉选择，或点击 **选择目录…** 打开系统目录选择器。
3. 点击 **添加工作区** 加入更多成员，一个组可包含 2–20 个工作区。每个成员都可以填写显示名称和项目角色。
4. 填写协作备注，例如“前后端共用 API 契约，修改接口时同步检查两边”。
5. 点击 **保存关联组**。组内任意工作区后续都能自动获得其他成员的上下文。

已有组以卡片展示全部成员的名称、路径、角色和备注。可以按名称、路径、角色或备注搜索；点击 **编辑** 可以增减成员、更换目录或修改名称、角色和备注。成员的角色或备注留空即可清除。

点击 **解除关联** 后，页面会要求再次确认。解除只删除整组关系，不删除工作区、会话或任何项目文件。点击 **刷新** 可重新读取工作区和关联组列表。

## 自动上下文

当前目录与组内任意成员相同或位于其内部时，插件会把同组其他所有工作区的名称、绝对路径、角色和备注加入动态上下文。无论从组内哪个工作区进入，都能看到其余成员，不再局限于两两端点。没有关联时不会增加上下文。若当前目录不再属于任何组，会继续按会话的原始工作区匹配。

自动上下文最多列出 20 个关联工作区，每个备注最多保留 300 个字符；完整记录可在设置页查看。

关联只提供项目位置和说明，不扩大当前会话的沙箱或审批权限，不读取或修改目标目录，也不自动启动其他会话。若当前权限不允许写入关联目录，仍需按 DSH 的权限流程处理。

## 可选 AI 工具

插件仍提供 `workspace_links` 工具，便于 AI 查询关联，或在用户明确要求通过 AI 建立、解除关系时使用。设置页与工具调用同一个 `workspaceLinks` Host 服务及同一份 Profile 配置，不会形成两套数据。

`action` 支持 `list`、`link`、`group`、`unlink`。`link` 建立两个工作区的关联，`group` 用 `members` 数组建立 2–20 个工作区组，`unlink` 解除当前工作区与目标的关系。建立关联时目标目录必须存在；插件会通过 DSH 工作区注册表取得规范化路径。解除关联会解析仍存在的 junction/符号链接别名；若目录已不可访问，可按配置中的原始绝对路径解除陈旧关联。省略字段会保留原值，显式传入 `null` 或空字符串可清除角色或备注。

## 持久化与配置

关联组保存在当前 DSH Profile 中，由 `configEditor` 写入，重启后保留。旧版两两关联会自动视为两人组，无需手工迁移。默认配置如下：

```yaml
- insert:
    - id: workspace-links
      name: 'dsh-workspace-links'
      config:
        relations: []
```

每个 `relations` 条目包含 2–20 个工作区端点及可选备注。建议通过设置页修改，不必手工编辑配置。禁用插件后不会再注入关联上下文，也不会提供设置页和 `workspace_links` 工具，但已保存的配置仍保留。

## 限制

- 需要包含 `workspaceRegistry`、`workingDirectory`、`systemPrompt`、`tools`、`configEditor` 和 `typert` 服务的 Host，以及 Remote、设置页和目录选择器 Client 能力；当前桌面 Web Profile 已具备这些服务。
- 安装或升级 Client 页面后，如果当前 GUI 尚未刷新，请刷新一次页面以加载新的客户端模块。
- 本版本集中管理 2–20 个工作区的全互通关联组，不自动分析前后端接口或启动多代理协作；AI 可根据已提供的路径使用现有文件、终端和子代理能力继续工作。

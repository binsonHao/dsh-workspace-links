# 工作区关联

这是一个 DeepSeek Harness 插件，用来可视化管理工作区之间的关联，并在每次模型请求时按当前会话目录提供相关项目上下文。

## 安装

在 DSH 的 **插件 / Plugins** 页面选择添加插件，填入本仓库的 GitHub 地址即可。安装后如当前页面尚未加载新插件，刷新一次 GUI。

仓库地址：<https://github.com/binsonHao/dsh-workspace-links>

## 可视化管理

打开 **设置 → 工作区关联**。页面提供完整的关联管理，不需要通过对话或记忆命令：

1. 点击 **新建关联**。
2. 在“工作区 A”和“工作区 B”中，从 DSH 已有工作区下拉选择，或点击 **选择目录…** 打开系统目录选择器。当前会话所属工作区会作为 A 的默认选择，并在相关卡片上标记“当前工作区”。
3. 可选填写双方显示名称、项目角色和协作备注。例如 A 为 Vue 前端，B 为 Spring Boot 后端，备注为“前后端共用 API 契约”。
4. 点击 **保存关联**。新关系会立即出现在列表中，AI 后续请求也会自动获得对应上下文。

已有关系以卡片显示两个项目的名称、路径、角色和备注。可以按名称、路径、角色或备注搜索；点击 **编辑** 修改名称、角色和备注，留空单项角色或备注即可清除。编辑时目录保持不变；如需更换目录，请新建关联后解除旧关联。

点击 **解除关联** 后，页面会要求再次确认。解除只删除关系，不删除工作区、会话或任何项目文件。点击 **刷新** 可重新读取工作区和关联列表。

## 自动上下文

当前目录与某个关联端点相同或位于其内部时，插件会把另一端的工作区名称、绝对路径、角色和备注加入动态上下文。双向关联会在两个工作区中分别呈现对方视角。没有关联时不会增加上下文。若当前目录不再属于任何关联端点，会继续按会话的原始工作区匹配。

自动上下文最多列出 20 个关联工作区，每个备注最多保留 300 个字符；完整记录可在设置页查看。

关联只提供项目位置和说明，不扩大当前会话的沙箱或审批权限，不读取或修改目标目录，也不自动启动其他会话。若当前权限不允许写入关联目录，仍需按 DSH 的权限流程处理。

## 可选 AI 工具

插件仍提供 `workspace_links` 工具，便于 AI 查询关联，或在用户明确要求通过 AI 建立、解除关系时使用。设置页与工具调用同一个 `workspaceLinks` Host 服务及同一份 Profile 配置，不会形成两套数据。

`action` 支持 `list`、`link`、`unlink`。建立关联时目标目录必须存在；插件会通过 DSH 工作区注册表取得规范化路径。解除关联会解析仍存在的 junction/符号链接别名；若目录已不可访问，可按配置中的原始绝对路径解除陈旧关联。重复建立同一关联时，省略字段会保留原值，显式传入 `null` 或空字符串可清除角色或备注。

## 持久化与配置

关系保存在当前 DSH Profile 中，由 `configEditor` 写入，重启后保留。默认配置如下：

```yaml
- insert:
    - id: workspace-links
      name: 'dsh-workspace-links'
      config:
        relations: []
```

每条关系包含恰好两个工作区端点及可选备注。建议通过设置页修改，不必手工编辑配置。禁用插件后不会再注入关联上下文，也不会提供设置页和 `workspace_links` 工具，但已保存的配置仍保留。

## 限制

- 需要包含 `workspaceRegistry`、`workingDirectory`、`systemPrompt`、`tools`、`configEditor` 和 `typert` 服务的 Host，以及 Remote、设置页和目录选择器 Client 能力；当前桌面 Web Profile 已具备这些服务。
- 安装或升级 Client 页面后，如果当前 GUI 尚未刷新，请刷新一次页面以加载新的客户端模块。
- 本版本集中管理双向工作区关系，不自动分析前后端接口或启动多代理协作；AI 可根据已提供的路径使用现有文件、终端和子代理能力继续工作。
